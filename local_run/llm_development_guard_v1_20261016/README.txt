Full development guard v1, prepared 16 October 2026

Status at preparation: SOFTWARE ONLY. No admitted threshold, full guard, post-guard
panels, repair experiment or evaluation result exists for this package. The active
calibration controller owns all ongoing model work. Do not duplicate its stages.

This version binds the completed intake and resource pilot, and prepares a full
10314 by 42063 guard (433837782 pairs). It uses the unchanged qualified indexed
scanner, native FP32 E5 cache and frozen ordered FP64 scorer. A second fresh
process runs the original semantic_guard over the same entire scope, including
its explicit gathered FP32 subset. A third process requires exact retained IDs,
canonical stable-ID witnesses and scores and independently reconstructs whole
surviving source prefixes. Both scanners share the frozen numerical scorer;
this is not an independently implemented cosine arithmetic audit.

Admission is deliberately separate from execution. The local preparer requires
an actual positive terminal controller result, successful selection and fresh
validation reviews, and ten exact remote artifacts. It replays all 51 selection
cuts, weighted denominators, the least strict qualifying threshold, strict score
comparisons, the exact finite-population lower bound, and all canonical overlap
status/category comparisons. It binds the executed frame, package identities,
activation and request differences, source samples and independent review bytes.
A missing or failed result creates no bundle. There is no threshold override.

Operational sequence (no launch is implicit in these instructions):
1. Reconcile the existing controller, local receipts and Slurm. On negative
   selection/validation, preserve the negative and follow the queue failure
   branch. On transport failure stop remote attempts until access is restored.
2. After positive terminal calibration only, execute export_admission_remote.py
   from the staged package. It reads ten fixed small artifacts and emits a private
   base64 transport payload. Save stdout under the private orchestration folder.
3. Locally run prepare_admission.py --controller <completed-controller-directory>
   --export <saved-private-export.json> --output <new-private-directory>.
   Keep its 13 source files and admission.json private. Do not publish the bundle.
4. Stage those exact files, exclusively, at the fixed common.BUNDLE location;
   verify all bytes and the returned admission_sha256. Never replace an occupied
   package, admission or execution slot. Reconcile any ambiguous earlier write.
5. Once no Third stage is active and the completed controller has no further
   transitions, run launch.py from the staged package with --package-sha256
   <sha256-of-package_manifest.json> --admission-sha256 <sha256-of-admission.json>.
   It rechecks the gate, frozen checkout, source identities, empty Third queue,
   and fresh quota before one exclusive launch intent and one sbatch call.
6. Verify terminal COMPLETED/0:0, pipeline_completion.json, result.json, every
   process receipt, raw private panel/guard payload and input binding before
   accepting panels. No effect experiment launches automatically.

Resource scope: cpu-short, cn1, 2 CPUs, 8 GiB, one numerical thread, no GPU,
3600-second Slurm limit. The resource pilot's approximate 1288 seconds per scan
is a linear projection, not an ETA. Two full scans, admission, hashes and output
work may exceed the cap. Preserve a timeout/failure without automatic retry.
Quota requires the unchanged 8 GiB reserve plus a 256 MiB stage allowance;
publication is capped at 128 MiB, the admission bundle at 32 MiB and each child's
combined logs at 4 MiB. wait4 records this exact child's peak RSS, avoiding a
cumulative sibling maximum. Scan timing is separate from whole-child lifecycle.
Native runtime and software fixtures are checked inside the job before scans.
The locally passed suite does not claim native Slurm or natural full-run success.

Original calibration/test membership stays fixed. Only reserved development
training can be removed. The original development order and targets 1000, 2500,
5000 include the complete surviving boundary source and retain any shortfalls.
All reserved sources stay excluded from later evaluation, even if unused.
Development utility may eventually use only the 2138 reserved test rows; the
18929 later evaluation-test labels are not read here. Raw text and task-label
files are hashed for lineage, never decoded or used by this stage. Contributor
proxies and unknown singleton limitations remain. No new human review exists;
original human and primary gates remain unmet.

INHERITED_SOURCES.json binds the exact copied scanner, guard tests, reservation
plan and statistics fixture implementation. fixture_statistics.py is used only
to produce synthetic expected reports in tests; production admission has its own
arithmetic and does not import it. Synthetic counts and labels are software
fixtures, never study evidence. The suite exercises gates, strict boundaries,
negative outcomes, exact bounds, overlap changes, complete artifact bindings,

repeat-launch prevention. SOFTWARE_VALIDATION.json records the actual local run.
