Versioned E5 calibration-frame adapter — 14 October 2026

This adapter reads the completed version-2 sharded CPU cache and emits a
distinct calibration frame. It does not impersonate the frozen Phase 4 cache
schema, run an encoder, sample pairs, collect judgments, select a threshold,
or execute the original monolithic writer/replay. The current user-directed
continuation is LLM-only; this adapter has no human-annotation prerequisite.
It makes no human-validity or semantic-quality claim.

ADMISSION AND EXACT TARGET
Expectations pin the current core/dispatch packages, completed qualification,
SciPy repair, full plan, source ordering, and the actual assembly manifest and
payload references from job 13546. Production execution is Linux Slurm only,
using the existing encoder-cpu interpreter on the same qualified CPU/runtime.
No download, install, external API, scheduler submission or retry occurs here.

The unchanged core's context and qualification validators check source replay,
complete census, source view/audit, assets, frozen source, runtime, qualification
golden/encoded/replayed vectors and logs. The adapter rebinds the additive SciPy
repair separately; the core numerical fingerprint is not whole-env identity.
It recomputes the full prospective plan and verifies all 140,250 rows in their
original order. It loads full source/census rows once; per-shard checks receive
the corresponding slices, avoiding 32 repeat source scans.

Before gathering, it hashes the actual 430,848,128-byte full NPY and
75,706,969-byte full log against the pinned manifest. For each of 32 ranges it
calls the unchanged encoded-shard and replay validators on actual files, then
compares every full-cache FP32 slice and parsed log slice with that encoded
shard. Complete content-token/chunk/batch counts must match. Exact recorded
dispatch/child CLI, artifact links, positive distinct encode/replay child PIDs,
through-exit timers and inherited claim boundaries are checked. The assembly
manifest must bind the same 32 ordered completion pairs. No passed boolean or
metadata-only review substitutes for these current payload checks.

The native source unit and 70/15/15 hash partition are recomputed for every
retained source row using the unchanged phase3.panels functions and exact salt.
The study-design hash and preparation audit must agree. Unknown/nonpositive
owner IDs remain explicit unknown singletons. Native accounts are contributor
proxies, not proof of all actual authors or publisher authenticity.

All 20,996 calibration records are gathered, in full source order, as exact
FP32 bytes. No length, owner-availability, tag, judgment, score or other filter
is applied. Source-disjoint means separation between partitions: pairs sharing
a source within calibration remain eligible. The unordered universe is all
i<j, exactly 220,405,510 pairs. Fixed guards are not rerun on the subset.

OUTPUTS AND BYTE BUDGET
Only a fresh private directory beneath WORKSPACE/qualification is permitted.
Symlinks in supplied/source-output paths and overwrites are refused.
  vectors.npy                 20,996 x 768 FP32; 64,499,840 bytes with NPY header
  records.private.jsonl       calibration/full-row index, ID, source, kind,
                              partition and UTF-8 text SHA; no body text
  input_bindings.json         original source/cache/package/evidence hashes
  result.json                 separate third-e5-calibration-frame-v1 receipt,
                              sealed and published last; passed=false on failure
The receipt seal hashes its own fields except sha256 using sorted compact JSON,
ensure_ascii=True, allow_nan=False. This is a new schema with explicit ancestry;
it is not an old calibration pack or a scientific admission certificate.

Before writes, serialized row metadata is capped at 16 MiB, input bindings at
4 MiB and the final receipt at 2 MiB. Together with the exact vector file these
fit the enforced 96 MiB frame-directory allowance. All source inputs are read
only. Full text, full vectors and chunk logs are not copied into the new frame.
The separate root launcher accounts for console logs, filesystem overhead,
contingency and the unchanged quota reserve; this package never changes quota.

After durable writes, the gathered vectors are reread and compared bytewise to
every selected original row. All input/code/asset bindings and exact payload
inventories are checked again before the passed result is atomically published
without replacement. Failed or incomplete directories remain evidence and are
never resumed, silently repaired or overwritten. Timing includes heavy source,
asset and payload validation; the result's timer ends before its own publication.
Root's wrapper separately records the whole child through exit and console costs.

LATER TEXT LOOKUP AND CLAIM LIMITS
Downstream code must use original_full_row_index against the bound original
source and require record_id and text_sha256 equality, rather than relying on
vector position alone. The exact source bytes, canonical full-row/text/order
digests and preparation audit remain bound in the input receipt and result.
Calibration ordered IDs, ordered source IDs and full-row indices are also sealed.

actual_cache_payload_hashes_verified and frame-gather checks may pass under this
new adapter. source_authenticity_verified, original_route_acceptance,
full_population_cache_acceptance, semantic_validity_established and
confirmatory_study_ready remain false. Later LLM sampling/rating needs its own
versioned lock and schemas. This stage creates zero human responses and zero
model judgments, and draws no scientific sample.

CLI (root supplies every absolute path and the externally reviewed package SHA)
frame.py --repo R --workspace W --view V --replay-result SR --census-dir C
  --budget-dir B --qualification-result Q --qualification-sha256 QSHA
  --plan P --assembly-root FULL_ROOT --repair-result RR
  --frame-package-sha256 PACKAGE_SHA --out NEW_PRIVATE_DIRECTORY

The reviewed core SHA is fixed in expectations and passed internally to its
context; there is no caller-selectable numerical implementation. The full root
and full-plan relative path are fixed. Expected Slurm wrapper resources are
2 CPUs / 48 GiB / 20 minutes on qualified csis.cn1, cpu-short, exclude csis.mn1,
propagate=NONE, offline and OMP/MKL/OPENBLAS threads 1, CUDA_VISIBLE_DEVICES empty.

LOCAL SOFTWARE CHECKS
THIRD_FRAME_REPO=/absolute/repo python3 -m unittest discover -s PACKAGE -p test_frame.py -v
The environment override is required when the package is privately staged away
from the repository. Sixteen bounded synthetic software tests need NumPy only.
They cover complete calibration retention, same-source inclusion, unknown
owners, reordered/missing/duplicate rows, changed source/partition fields,
wrong manifests/counts/shards, FP32 byte gathering, corrupt vectors, exclusive
publication, path/package integrity and output budgeting. No model is invoked.
Separate local compatibility evidence replays the actual copied 32 shard and
one assembly metadata records through the exact command/receipt checks (65
child commands). It does not simulate Slurm or independently read remote data.
Full production admission is unexecuted by local software validation and must
pass under the actual Slurm source/assets/runtime before a frame is usable.
