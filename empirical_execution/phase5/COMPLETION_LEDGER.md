## Remaining activation, acceptance and measurement limits

This section distinguishes implemented branches from work that their APIs and engineering checks cannot establish. A common registry now preserves 43 configuration groups, 16,933 planned jobs and 158 required artifact keys. Its 21 explicitly unresolved protocol obligations are recipe/gate entries, not a claim that every associated algorithm is absent. These are planned jobs, not completed experiments or an externally submitted preregistration.

1. **Study-wide primary activation and execution.** The Phase 4 dossier inspector deliberately keeps `execution_allowed=False`. The registry/preflight enumerates jobs and rejects incomplete inventories; branch executors now exist for task, method-service, convex, refit and boundary work. They are not an accepted primary dispatcher that applies every real-data guard, joins every method under the same policy and attaches all registered analyses. That input-dependent integration must be completed and audited against the actual supplied assets. Primary activation requires a versioned acceptance route, not editing an evidence-role string or treating a checksum as authenticity.
2. **Versioned numerical acceptance.** `decoders.py` implements normalized residual `eta <= 1e-10`, condition reporting, compensated products, zero-start CG and separate extended-precision evaluator diagnostics. `workers_v2.py`/`run_isolated_v2.py` integrate this policy; their final 18-service/36-release check passed. Two earlier joint-span symmetry-interface failures and their original code are preserved; the versioned packed-upper reconstruction correction did not loosen the gate. The already frozen 216-job v1 run is separate evidence. Actual primary-scale acceptance remains to be performed. Neither ordinary nor extended residuals are interval certificates; the historical strict-rational service remains a separate target/implementation.
3. **Convex primary acceptance.** The full three-arm driver is now implemented; its eligible-payload arms own actual permitted feature/target rows rather than receiving every original array. Record/source paths, all retained queries, persistence and held-out-array evaluation are supported. Primary activation remains refused pending authentic inputs and the shared acceptance workflow. The default 2,000,000-coordinate exact-verification budget can be exceeded at native10k/768/20 scale; the configurable budget and actual feasibility must be locked on development, with over-budget failures retained. Current natural checks use their explicitly disclosed reused evaluation pool. Shared-process execution cannot supply the isolated primary systems panel.
4. **Utility and sensitivity activation.** `task_program.py` now executes curated/uncurated/hash/logistic utility and oracle/B-F task effects, including a supplied two-by-two encoder cross, exact threshold alternatives with fresh quality requirements, seeded orthonormal projections and conditioning/priority alternatives. It checks training/evaluation/calibration separation and does not substitute missing encoders. Its preserved lexical Civil82/18 verification is development evidence. This task slice explicitly leaves FP32/CG and additional repair-method cells to their own service executors; only joining those actual outputs can complete the corresponding full-method sensitivity jobs.
5. **Human scientific interpretation.** Response ingestion, weighted estimates, agreement, skip/truncation bounds, adjudication and deterministic example IDs are implemented in `human_analysis.py`. The actual response files remain blank. Design-based confidence intervals for human category prevalence are not implemented; reported missingness bounds must not be called such intervals. The protocol's genuine independent collection, rights/consent and substantive interpretation cannot be supplied by code.
6. **Measurement boundaries.** V2 workers add hashes for loaded ELF dependencies/runtime versions, `/proc/self/io` read-stage quantities, exact explicit write-call bytes and B-E payload-value byte equivalents derived from recorded row accesses. These supplement RSS, file/snapshot/head sizes and lifecycle time. They do not measure exact physical memory/cache traffic, every metadata/compaction access, aggregate simultaneous process-tree peak RAM or full allocator attribution; those values remain null/unclaimed. Loaded-module fingerprints do not prove a complete transitive dependency closure. `wait4` block-operation counts and logical file lengths must retain their distinct units. Remaining measurements need defined instrumentation, not invented sums of unrelated peaks.
7. **Scientific acceptance of unexecuted real backends.** Local transformer and official Faiss/upstream SemDeDup adapters are implemented but unexecuted. Supplying dependencies is necessary; an actual pinned-backend integration/acceptance run is still work to perform. Software mocks/reference implementations cannot discharge this gate.

## Requirements that code alone cannot finish

- Authentic original corpus assets, verified coverage/permissions and native source identities.
- Pinned real model/tokenizer bytes and usable local runtime, followed by actual inference and cache checks.
- Genuine independent human calibration, validation and interpretation responses with the documented collection process.
- Disjoint development measurements for configuration, precision/power and common resource limits before locking confirmation.
- The entire native semantic experimental matrix, all source and replication arms, recorded failures and the final scientific interpretation. Zero/negative results remain results and cannot be replaced with favorable configurations.

The available project is substantially more executable than Phase 4, including an actually enforced no-reaccess worker and stronger baselines. **It is neither an all-TODO-complete repository nor an ACL-ready empirical result set.** The exact remaining boundaries above should travel with the code and future continuation context.
