Indexed ridge summary implementation notes (2026-10-04)

Public interface
  from ccu.summary import IndexedRidgeSummary, preflight, SummaryMemoryError
  forecast = preflight(blockers, d, C, horizon, owners=None, universe_size=None)
  state = IndexedRidgeSummary.build(
      features, targets, blockers, horizon, owners=None, universe_size=None,
      max_coefficient_bytes=512 * 1024**2)
  counters = state.delete(integer_identifiers)
  gram, cross, count = state.statistics()
  solution = state.decode(lambda_reg)    # identical ccu.core decoder
  weights = state.solve_ridge(lambda_reg)
  live_accounting = state.accounting()
  state.check_invariants()              # full scan, outside measured repair
  state.save(path)                      # full-state export, separately charged
  resumed = IndexedRidgeSummary.load(path)

Features are canonicalized to FP32 then promoted to FP64 for multiplication.
Targets are FP64. Record identifiers are 0,...,N-1. In source mode, owners
contains one integer source assignment per record; universe_size declares the
public source universe. Blocker lists always contain record indices, even in
source mode. They need not use row order as priority order. The external fixed
curator determines which valid raw records block each record.

No retained rows or original graph are stored in the resulting state. It holds
current coefficient arrays, live inverse/degree indices, public integer-ID
membership, dimensions, and the remaining horizon. It returns a head/moments;
selected record identities cannot be recovered from this state. This claim is
about fields/code, not process isolation, allocator erasure, backups, or logs.

The cap is a numeric-coefficient allocation cap, NOT a process RSS cap. The
preflight computes distinct structural keys, incidence rank, eligible records,
and native-dimension coefficient bytes before allocating coefficient arrays.
Python structural metadata, caller-held rows, temporary products, encoder state,
and solve workspace are additional. Actual coefficient count can be smaller
through exact cancellation. The metadata forecast is not a nonlinear/PSD-ridge
information lower bound.

Updates use inverse and degree buckets. Only touched entries move; vector
addition and exact-zero checks occur on collisions. Full scans in accounting,
invariant checks, coefficient exports, saving, and model decoding are explicit
and must not be included/excluded inconsistently in benchmarks. Construction
and checkpointing must be timed separately. The code is a Python/NumPy research
implementation, not evidence of optimized systems superiority. Saving creates
a second dense coefficient matrix, and its transient peak must be counted.

Requests are validated before mutation. Duplicate/repeated public identifiers
are rejected atomically, matching B-E; rejected requests consume no horizon. The horizon
never resets. Unknown identifiers and excessive requests raise ValueError. In
source mode, same-source blockers cancel their record's polynomial identically.

Only exact-zero coefficient vectors are pruned. Different floating accumulation
histories need not be byte-identical to each other or a fresh rebuild. All
current moment drift remains visible in statistics(). For count exactly zero,
decode applies the declared zero-head convention while preserving raw drift for
audit; the common decoder receives zero moments in this one empty-target case.
No nonempty matrix is projected to PSD, jittered, rounded, or silently rebuilt.
No historical checkpoint/head or data reread is used as fallback.
